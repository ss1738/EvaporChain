## CRITICAL (mainnet-blocking)

### PRIV-N1 — Empty-siblings Merkle proof accepts arbitrary commitments
- **File:** `crates/evaporchain-proving/src/privacy.rs:235-253` (`verify_merkle_proof`)
- **Caller:** `crates/evaporchain-execution/src/privacy_exec.rs:588, 804`
- **Vector:** `MerkleProof { siblings: vec![], leaf_index: 0, root: <anchor> }` makes the verify loop run zero iterations. `current == proof.root` reduces to `input_note_commitments[i] == tx.anchor`. Attacker submits unshield with `input_note_commitments[i] = current_anchor` + any value commitment / amount / blinding + matching balance binding → mints unlimited from shielded pool.
- **Fix:** require `siblings.len() == NoteTree::depth` AND `leaf_index < (1 << depth)`.

### PRIV-N2 — `restore_from_db` doesn't repopulate nullifier_set or PNT window
- **File:** `crates/evaporchain-execution/src/privacy_exec.rs:313-349`
- **Vector:** After restart on `protocol_version >= 1`, in-memory `engine.nullifier_set` is empty AND the PNT live-window is empty. v0 path is OK (`db.is_nullifier_spent` first), but the v1+ path at line 291 reads `pnt.is_spent_in_window(...)` exclusively. Every previously-spent nullifier replays the moment the chain flips to v1.
- **Fix:** replay persisted nullifiers into `engine.nullifier_set` + persist/reload PNT live-window phases on `restore_from_db`.

### SCR-N1 — Cross-contract `caller` is the original EOA, not the calling contract
- **File:** `crates/evaporchain-script/src/vm.rs:879`; `crates/evaporchain-script/src/lib.rs:443-450`
- **Vector:** Contract A calls B; B sees `ctx.caller == EOA` instead of A's address. Any `require(caller == owner)` gate B has is bypassable by any user routing through A.
- **Fix:** introduce per-contract identity address; pass that (not `ctx.caller`) as the callee's `caller`; expose EOA separately as `origin`.

## HIGH

### PRIV-N3 — Balance-amount overflow in privacy execution
- **File:** `crates/evaporchain-execution/src/privacy_exec.rs:594, 595, 818-819`
- **Vector:** `input_amounts.iter().sum::<u64>()` overflows. Release: wraps `sum_in` to small value; attacker computes matching `balance_binding` (owns blindings); `sum_in < tx.amount` passes; unshield > inputs. Debug: panics → validator crash.
- **Fix:** `try_fold(0u64, u64::checked_add)` returning `BalanceOverflow`.

### PRIV-N4 — `balance_binding` lacks tx-kind DST
- **File:** `crates/evaporchain-proving/src/privacy.rs:520-547` (`compute_balance_binding`)
- **Vector:** `Poseidon(sum_in || sum_out || fee_or_amount || blindings...)` with no tx-type tag. A binding for `UnshieldTx{amount=A, change_total=C}` is bit-identical to `PrivateTransferTx{fee=A, sum_out=C}` for the same blindings → cross-type replay/grinding on overlapping blinding sets.
- **Fix:** prepend `b"unshield"` / `b"xfer"` discriminant byte to Poseidon preimage in both compute + verify.

### DRIFT-N3 — Proposal BLS signature accepted as `None` during "migration"
- **File:** `crates/evaporchain-consensus/src/tendermint.rs` (per commit `a866d3aa`)
- **Vector:** Verifier path accepts `bls_signature: None` via migration-window comment. HIGH gossip-forgery vector remains exploitable; the V-class addendum marks V2 closed.
- **Fix:** remove the "Accept during migration" branch and reject `None` outright; if migration window is real, flag a `BLS_REQUIRED_FROM_HEIGHT` constant gate.

### ✅ SUB-N1 — App-templates-eventlog Merkle proof no tree-size binding (CLOSED commit `e949e15c`)
- **File:** `crates/evaporchain-app-templates-eventlog/src/merkle.rs:53-70` (`verify_inclusion`)
- **Vector:** Proof commits neither tree-size nor leaf count. Crafted `(idx, path)` reaching the root by chance certifies a non-leaf interior hash as a "receipt." Classic Merkle tree-size confusion.
- **Fix:** include leaf count in the commitment (root over `(count, leaves)`); reject `path.len() != ceil(log2(count))`.

### ✅ SUB-N2 — 20 per-template `parse()` calls with no calldata length cap (CLOSED commit `7b21fbc9`)
- **File:** `crates/evaporchain-app-templates-engine/src/init_*.rs` (×20 files)
- **Vector:** Every `parse()` calls `serde_json::from_slice(calldata)` with no length pre-flight; `init_singh_lineage` deserializes `Vec<LadderRung>`, `init_sgb/ssm/scl/sfsv` deserialize unbounded `String`. Multi-MB calldata forces parse-tree alloc before any gas check.
- **Fix:** enforce `calldata.len() <= MAX_INIT_CALLDATA` (e.g. 64 KiB) in `dispatch::materialise` before calling any `parse()`.

### ✅ SUB-N3 — HBCT transfer breaks Layer-0 conservation (CLOSED commit `62b77fe0`)
- **File:** `crates/evaporchain-hbct/src/book.rs:50-79` (`HbctBook::transfer`)
- **Vector:** Debits `from` for full `amount` but credits `to` via `saturating_add`. If `to`'s balance is near `u64::MAX`, credit silently clips while debit lands → total MWh on books decreases.
- **Fix:** `checked_add` on credit side; reject before touching `from`.

### ✅ SCR-N2 — Constant folder saturates; runtime checks (CLOSED commit `c0a067ab`)
- **File:** `crates/evaporchain-script/src/compiler.rs:546-548` (`fold_binop`)
- **Vector:** `u64::MAX + 1` folds to `u64::MAX` (Push); runtime would `Err(arithmetic overflow)`. Auditor comparing "what source says" vs "what chain runs" misled. Adversarial author can turn conservation/auth predicates into constant true/false.
- **Fix:** `checked_*` in `fold_binop`; refuse to fold on overflow / div-zero / mod-zero.

### ✅ SCR-N3 — Cross-contract sub-call state patches don't roll back on parent error (CLOSED commit `c0a067ab`)
- **File:** `crates/evaporchain-script/src/lib.rs:465-467`
- **Vector:** A → B (B mutates own storage, returns Ok) → A errors after B returned. Router still applies B's state_patches and emits B's events → atomicity break.
- **Fix:** snapshot `state_patches.len()` + `collected_events.len()` before `call_external`; truncate on Err.

### ✅ SCR-N4 — `Value::to_map_key` collides all Maps and all Arrays (CLOSED commit `c0a067ab`)
- **File:** `crates/evaporchain-script/src/lib.rs:70-71`
- **Vector:** `Value::Map(_)` always returns `"m:map"`; `Value::Array(_)` always `"r:array"`. Composite map-keys alias to same slot → silent collision, lost writes, wrong reads.
- **Fix:** reject Map/Array as map keys at `MapGet`/`MapSet`, or hash canonical serialization into the key.

### ✅ GEN-N1 — KeyAnnounce can overwrite genesis-anchored BLS without old-key continuity (CLOSED commit `49c9df79`)
- **File:** `crates/evaporchain-consensus/src/tendermint.rs:4666-4715`
- **Vector:** KeyAnnounce overwrites `vi.bls_public_key` for any `validator_id` whenever announced pk differs, gated only by self-consistent PoP on the new key. Off-path attacker who can gossip replaces a genesis-anchored BLS key with one they control; signs aggregate certs as that validator until real validator rebroadcasts.
- **Fix:** require continuity signature by currently-registered key over new pk (same shape as `apply_validator_key_rotations`); reject overwrite if a registered key already exists.
