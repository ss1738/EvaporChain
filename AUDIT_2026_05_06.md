## 2. CRITICAL Findings (must fix before external release)

### 🔴 CRITICAL-1: WASM crate live security risk

**Location:** `crates/evaporchain-crypto-wasm/src/lib.rs`

**Issues:**
- **Unsafe pointer math at lines 112–116** reconstructs Dilithium keypair from raw secret-key bytes assuming struct layout `{ public: [u8; PK], secret: [u8; SK] }`. If `pqc_dilithium` upstream changes layout (version bump, compiler change), silent memory corruption.
- **Secret key exposed to JS** via `kp.expose_secret()` returning `Uint8Array`. Safe ONLY in browser-extension context with proper CSP. If deployed in a webapp, any same-origin script reads WASM memory.
- **No key zeroing** — secret keys persist in WASM linear memory after signing. Caller must `.fill(0)` in JS, no enforcement.

**Reality vs claim:**
- Claimed 41,298 LOC, 3,491 tests
- Actual: **163 LOC, 5 unit tests** (claims were node_modules artifacts mistakenly counted)

**Fix:**
- Replace unsafe block with public API key extraction
- Document and enforce CSP requirements
- Add explicit `Drop` impl that zeros secret-key buffer
- Add integration tests for unsafe-path with mocked layout changes

---

### 🔴 CRITICAL-2: MCP server is an AI-agent attack surface

**Location:** `crates/evaporchain-mcp/`

**Issues:**
- **26 tools verified** — all forward agent JSON to chain backend with **zero input validation**:
  - `transfer`, `mint`, `burn` accept agent-provided amounts/addresses without range checks
  - `prove_fork_evaporated`, `compute_mera_commitment`, `check_conservation` allow agent to construct arbitrary chain proofs
- **Hardcoded node URL** `http://37.27.1.1:8080` at main.rs:23 — no TLS, no auth token, no mTLS
- **No rate limiting** — compromised agent can DoS the node
- **No logging** of which agent called which tool — attack forensics impossible

**Threat scenario:** Prompt-injection on any AI agent connected to this MCP → arbitrary chain state mutation without consent.

**Reality vs claim:**
- Audit doc claimed 771 LOC, 0 tests
- Actual: **1,689 LOC, 18 tests** (audit was wrong both ways)

**Fix:**
1. Add input validation per tool (range checks, address validation, schema enforcement)
2. Add API auth token requirement (mTLS or bearer token to backend)
3. Add per-tool rate limiting
4. Add audit log of every tool invocation
5. Mark write-tools (transfer/mint/burn) as requiring explicit agent consent prompt
6. Add TLS for non-localhost backend connections
