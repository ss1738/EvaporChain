EvaporChain Documentation

Complete guide to the EvaporChain testnet, API, and core concepts.

What is EvaporChain?

EvaporChain is a Layer 1 blockchain where every state object carries energy that depletes over time. When an object's energy reaches zero, it evaporates from the active ledger — but leaves behind a compact cryptographic proof called a ghost record. The result is a blockchain that gets lighter over time, not heavier.

Key properties:

  • Self-cleaning state — unused data evaporates automatically
  • Ghost records — cryptographic proof that evaporated data existed
  • Post-quantum signatures — ML-DSA (FIPS 204) from genesis
  • Dual state commitment — Verkle Trie + Merkle Mountain Range
  • 13 Rust crates, 356+ tests — modular, well-tested architecture

Send Your First Transaction

Create a state object with energy that will decay over time:

bashcurl -X POST https://testnet.evaporchain.com/api/tx/create-object \
  -H "Content-Type: application/json" \
  -d '{
    "owner": "YOUR_ADDRESS_HEX",
    "name": "my-first-object",
    "initial_energy": 1000,
    "half_life": 500
  }'

The object will start with 1000 energy and lose half every 500 epochs (~500 blocks). You can monitor its decay in the Explorer.

Thermodynamic State Decay

Every state object on EvaporChain has an energy parameter that decays exponentially over time, following the formula:

E(t) = E_initial * (1/2)^(t / half_life)

Where t is the number of epochs elapsed since the object was last refreshed, and half_life is the object's decay rate. This is identical to radioactive decay in physics.

Decay is passive — no one needs to trigger it. The network calculates current energy on-the-fly based on the timestamp.

Energy and Half-Life

Energy is the "fuel" that keeps a state object alive in the active ledger. Higher energy means longer lifespan. Energy can be refreshed by the owner at any time, resetting the decay clock.

Half-life controls the decay rate. A half-life of 1000 means the object loses 50% of its energy every 1000 epochs. Longer half-life = slower decay.

Half-life50% decay inUse case
100~100 blocksTemporary state, demos
5,000~5,000 blocksMedium-term storage
50,000~50,000 blocksLong-term assets

Object Lifecycle

Active
→
Grace Period
→
Ghost
  • Active — Energy > 0. Object is in the live state tree. Fully readable and writable.
  • Grace Period — Energy has hit zero. Owner is notified. 7-day window to refresh before evaporation.
  • Ghost — Object has been evaporated. Raw data removed from active state. A compact cryptographic proof (ghost record) remains permanently, proving the data existed and what it contained.

Ghost Records & Resurrection

When state evaporates, the network creates a ghost record — a compact proof containing:

  • The object's ID and final state hash
  • Timestamp of evaporation
  • Cryptographic proof of existence
  • Original owner address

Resurrection: Within 30 days of evaporation, the original owner can resurrect a ghost object by paying a small energy fee. After 30 days, the ghost record is permanent but the object cannot be restored.

bashcurl -X POST https://testnet.evaporchain.com/api/tx/resurrect \
  -H "Content-Type: application/json" \
  -d '{"object_id": "OBJECT_ID_HEX", "owner": "OWNER_ADDRESS_HEX"}'

View all ghost records:

bashcurl https://testnet.evaporchain.com/api/ghosts

EVR-721: Mortal NFT Standard

EVR-721 is EvaporChain's NFT standard. Unlike ERC-721 on Ethereum, EVR-721 NFTs carry energy and decay over time. Key differences:

  • Energy — Each NFT has an energy parameter that decays
  • Half-life — Controls decay rate per NFT
  • Evaporation — NFTs evaporate when energy reaches zero, leaving ghost records
  • Refresh — Owners can refresh NFT energy to extend lifespan
  • Collections — NFTs are grouped into named collections

Use the /api/nft/mint, /api/nft/transfer, and /api/nft/refresh endpoints above.

EVR-20: Decaying Fungible Token Standard

EVR-20 is EvaporChain's fungible token standard. Token supplies decay over time:

  • Supply decay — Total supply decreases based on decay_half_life
  • Per-holder decay — Individual balances can decay independently
  • Deploy — Anyone can deploy a new EVR-20 token via the API

Use the /api/token/deploy, /api/token/transfer, and /api/token/balance endpoints above.

Post-Quantum Cryptography

EvaporChain uses ML-DSA (Module-Lattice Digital Signature Algorithm, FIPS 204) for all signatures from genesis. This is the same standard selected by NIST for post-quantum digital signatures.

  • All transaction signatures use ML-DSA
  • Block producer signatures use ML-DSA
  • No classical signature fallback — quantum-safe only
  • Addresses are derived from ML-DSA public keys
