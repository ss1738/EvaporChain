# EvaporChain code audit — 2026-05-13

Code-only audit across consensus, execution+privacy+script, crypto+keys, network+DA, and bridge+state.
Five parallel auditors, each briefed with the 2026-05-11/12 closure list to avoid re-reporting.

**Result: 46 NEW findings — 5 CRITICAL, 13 HIGH, 18 MEDIUM, 10 LOW.**

This is the largest audit yield since the chain's 2026-04-24 round. Several findings (the 5 CRITICALs especially) contradict claims in `DOCTRINE_PUNCH_LIST.md` that all 7 layers are ✅ DONE — the punch list is correct that the **trait surfaces** exist; this audit shows the **production hot path (`ParallelExecutor`)** was never brought to parity with `SimpleExecutor` on multiple transaction types, and that two cryptographic primitives (Energy-Verkle exclusion proofs, NMT proofs) accept structurally-valid forgeries.

## 2. CRITICAL findings — must be fixed before any mainnet wiring

### C1 — Energy-Verkle exclusion proof verifier short-circuits on `hit_compressed`

**File:** `crates/evaporchain-crypto/src/energy_verkle.rs:727-740`

```rust
pub fn verify(proof: &EnergyVerkleProof, expected_root: &[u8; 32]) -> bool {
    if proof.depth > MAX_DEPTH { return false; }
    if proof.depth == 0 {
        if proof.value.is_none() {
            return *expected_root == [0u8; 32] || proof.hit_compressed;
        }
        // ... real leaf-hash path follows
    }
```

Any party can construct `EnergyVerkleProof { depth: 0, value: None, hit_compressed: true, … }` and pass verification against any `expected_root`. No key, no path, no work. Light clients, bridges, cross-shard verifiers consuming this primitive accept arbitrary "non-membership" claims.

**Fix:** Drop the `|| proof.hit_compressed` clause. A real hit-compressed proof must reconstruct the parent commitment chain and compare to root. Add an adversarial regression test: construct the forgery, assert `verify(&forgery, &any_root) == false`.

**Confirmed:** I read the literal code at energy_verkle.rs:733 — the disjunction is present. The `hit_compressed` field is `pub` on the struct (line 229), so the bit is attacker-controlled.

### C2 — NMT `verify_namespace_proof` never recomputes hashes up the Merkle path

**File:** `crates/evaporchain-da/src/namespace.rs:355-418`

The function only checks structural invariants: `start ≤ end`, `min ≤ max`, sibling-pair ordering. It never combines sibling hashes via `NmtNode::internal` to reproduce `proof.root.hash`. The absence path (`siblings.is_empty()` → `return start == end`) is the symptom PR #180 surfaced, but the inclusion path has the same defect — it returns `true` after range-checks alone.

**Exploit:** Forge `NamespaceProof { is_absence: true, namespace: any, root: real_root, siblings: vec![], start: 0, end: 0 }` → verifier accepts. Once cross-namespace fraud proofs or namespaced light-client paths come online, an attacker rewrites blob-existence claims for any block.

**Fix:** Add `recompute_root_from_siblings` that walks `range_siblings` bottom-up, combining via `NmtNode::internal` from claimed leaves (inclusion) or boundary leaves + siblings (absence), and reject if `recomputed.hash != proof.root.hash`. The current proof type may need extension to carry sibling positions (left/right per level) and claimed leaves.

### C3 — `ValidatorStake` silently burns balance on `ParallelExecutor`

**File:** `crates/evaporchain-execution/src/parallel.rs:1438-1465` (`exec_validator_stake`), `:467-470` (`OverlayStateDB::put_stake` is `{}`), `:1170` (dispatch into parallel path).

`SimpleExecutor::execute_validator_stake` (lib.rs:1668-1683) creates a `StakeRecord` via `db.put_stake(...)`. `ParallelExecutor::exec_validator_stake` debits `sender.balance` but never calls `put_stake`. Even if it did, `OverlayStateDB::put_stake` is `{}` — the record would never reach the main DB through `merge_overlay`.

**Net effect on production (CLAUDE.md identifies `BlockStmExecutor` / `ParallelExecutor` as the prod path):** Any user submitting `ValidatorStake` has `stake_amount` debited from balance, no validator registered, no recovery path — `ValidatorClaimStake` has no `StakeRecord` to find. Funds permanently lost.

**Fix:** Move `Transaction::ValidatorStake(_)` into the serial bucket at parallel.rs:1535-1554 alongside `ValidatorExit` / `ValidatorClaimStake`. Implement a serial arm mirroring SimpleExecutor's logic. Add E2E test: submit ValidatorStake → assert `db.get_stake(vid).is_some()`.

### C4 — 7 tx types blackholed by `ParallelExecutor`; T1.20 tests codify the bug

**File:** `crates/evaporchain-execution/src/parallel.rs:1535-1554` (serial-bucket filter), `:1208-1234` (parallel-partition error arms), `:1727-2034` (serial body falls to `_ => unreachable!()`).

The filter passes Governance / MultiSig / UserOp / UpgradeContract / Delegate / Undelegate / ClaimDelegation into the parallel partition. `execute_partition` then explicitly errors each with `"<class> txs execute in serial phase"`. The serial loop body has no arms for them — `_ => unreachable!()` would panic if the filter were corrected.

**Worst part:** The recent T1.20 tests at `parallel.rs:4631-4720` (`t1_20_governance_via_parallel_partition_fails` and siblings) assert `r.txs_failed == 1` — codifying the bug as desired behavior. SimpleExecutor has full arms at `lib.rs:3132-3214`.

**Production impact:** Governance proposals, multisig payments, account-abstraction user ops, contract upgrades, and the entire delegation lifecycle are non-functional on the prod executor. Users pay tx fees, see `success: false, error: "executes in serial phase"`, observe nothing happened. Per-tx fee is retained on a failed apply.

**Fix:** Extend serial-bucket filter to include all 7 variants; port SimpleExecutor arms into serial loop; rewrite the T1.20 tests to assert success paths; remove the error arms in `execute_partition`.

### C5 — Shielded pool absent from conservation domain; halt vector on enforce-flip

**File:** `crates/evaporchain-execution/src/energy_audit.rs:47-63` (`compartment_snapshot_with_pool`) reads accounts + stakes + refresh_pool. Never reads `db.get_shielded_pool_balance()`. Shield credits the pool at `privacy_exec.rs:427`, Unshield debits it at `:655-656`, PrivateTransfer fees go through at `:873-874`.

Under default `conservation_enforcement="observe"`:
- Every Shield trips `DecayExceededLambda` (Accounts ↓, no compensating credit anywhere).
- Every Unshield trips `DecayIncreasedTotal` (Accounts ↑ — looks like minting).
- Logged but blocks commit.

When the chain flips to `conservation_enforcement="enforce"` (the doctrine endgame), `evaluate_conservation_gate` at lib.rs:110 returns `Err(ExecutionError::ConservationViolation)` for every privacy tx. Privacy layer becomes unusable; any pre-existing privacy tx in a block at the flip boundary halts the chain via state-root mismatch.

**Fix (pick one):**
1. Add `Compartment::Shielded`; include `get_shielded_pool_balance()` in `compartment_snapshot_with_pool`; wire Shield as `Accounts → Shielded`, Unshield as `Shielded → Accounts`, PrivateTransfer fee as `Shielded → RefreshPool`.
2. Account for shielded pool inside RefreshPool compartment.
3. Pass shielded-pool delta as a legitimate redirect to `audit_block_step` (mirror the existing `minted_this_block` carve-out at parallel.rs:2382-2388).

## 3. HIGH findings — must be fixed before any cluster scale-out

### H1 — Compressed-region resurrection-insert silently drops commitment

`crates/evaporchain-crypto/src/energy_verkle.rs:352-382`. When `idx == 0`, the `if idx != 0 { internal.children.insert(0, node) }` skips re-inserting the compressed node. Historical state silently disappears from the root. Fix: place compressed node at a deterministic distinct slot (e.g. `idx ^ 0xFF` with refusal at collision), or refuse the insert and bubble up.

### H2 — Internal-vs-leaf hash collision

`verkle.rs:112-127`, `energy_verkle.rs:190-211`. Leaf = `blake3(key || value)`, internal = `point_to_bytes(commit)`. Same 32-byte type; verifier can't tell which kind was at a given depth. Fix: domain-separate with `b"evaporchain:verkle:leaf:v1\0"` and `b"evaporchain:verkle:internal:v1\0"`.

### H3 — Verkle and Energy-Verkle share Pedersen generators

`verkle.rs:32-44`, `energy_verkle.rs:32-44`. Both `format!("EvaporChain_Verkle_Gen_{i}")`. A commitment from one is structurally indistinguishable from the other at the same level. Fix: distinct seed prefixes per trie type. Hard fork — coordinate with genesis.

### H4 — MMR nullifier hashes lack domain tags

`accumulator.rs:31-39` (leaf), `:306-313` (internal node). Both bare BLAKE3 over preimages. Cross-protocol second-preimage attack on the nullifier set. Fix: prepend `b"evaporchain:nullifier:v1\0"` / `b"evaporchain:mmr:node:v1\0"`. Hard fork.

### H5 — DA certificate trusts attacker-supplied `total_stake`

`certificate.rs:46-49`. `is_supermajority` evaluates `attested_stake * 3 ≥ total_stake * 2` where both fields are deserialized from the cert. A single Byzantine validator V with stake `s` builds `{ attested = s, total = s, attestations = [V] }` — passes BLS sig check (`verify_signatures` only guards `attested ≤ Σ stake`) — gets accepted as supermajority. Fix: add `verify_signatures_with_set(&self, validator_set)` that recomputes true `total_stake` from local view; deprecate the keyless `is_supermajority()` for use on untrusted input.

### H6 — BlockSync integer overflow → unbounded alloc

`evaporchain-network/src/service.rs:1655-1673`. Peer sends `from_height = u64::MAX - 50, to_height = u64::MAX`. Validation passes. `from + MAX_SYNC_BATCH` wraps to `49` in release. `to.min(...) - from` underflows, casts to `usize` ≈ `2^64`, `Vec::with_capacity` OOM-kills the process. One-packet kill against any full node. Fix: `let span = to_req.saturating_sub(from).min(MAX_SYNC_BATCH); let to = from.saturating_add(span);`.

### H7 — DA sample seed predictable; producer biases coverage

`sampling.rs:223-249` + `main.rs:4594-4600`. Seed = `b"da-sample" || block.number || validator_id`. Both are public before block production. Byzantine producer enumerates all validators' queries, makes ONLY those shards available, withholds the rest. DA sampling soundness ("honest samples ⇒ data reconstructible") collapses. Fix: bind to Bell-beacon output (`evaporchain-bell-beacon`) or per-validator VRF revealed in the DA-attestation message.

### H8 — `verify_ghost_bridge_proof` keyless variant fails-OPEN

`evaporchain-state/src/ghost_bridge.rs:172-186`.

```rust
checks.attestation_valid = if structural_valid {
    match validator_pubkeys {
        Some(keys) => /* real BLS verify */,
        None => true,           // <-- silent bypass
    }
} else { false };
```

`verify_ghost_bridge_proof(proof)` calls into `_with_keys(proof, None)`. Any keyless verifier accepts cryptographically forged signatures as long as the byte shape is right. `GhostBridgeRegistry::new()::register` defaults to no keys. Bridge nonce check is the only defense, and it only prevents replay, not first-use of a forgery. **Fix:** make the keyless variant fail-CLOSED. Rename to `verify_ghost_bridge_proof_structure_only` for the legitimate "structural validity, signature deferred" use case.

### H9 — `ParallelExecutor` skips vesting gate

`parallel.rs:1336-1356, 1453-1458` check raw `sender.balance` instead of `sender.transferable_balance(epoch)`. SimpleExecutor (lib.rs:1217-1230) uses the vesting-aware path. **Net effect:** any user with a vesting schedule can pre-cliff transfer on the production executor. Mixing executors (test vs prod, alt client) causes fork. Fix: swap to `transferable_balance(epoch)` at both sites; keep `is_mint_bypass` carve-out for zero-address.

### H10 — `economics::compute_energy` violates Layer 0 invariant

`evaporchain-execution/src/economics.rs:27-45`. Uses `>>` on energy values (CLAUDE.md hard rule says only `evaporchain-types`) AND `f64` (architecture-dependent — non-deterministic across validators). Today only called from within `economics.rs`, but the `pub` visibility means a future caller silently breaks consensus determinism. Fix: delete or `#[deprecated] pub(crate) fn simulate_decay_lossy` rename + reroute callers through `evaporchain_types::energy_at_epoch`. Strengthen Layer 0 lint to grep workspace-wide.

### H11 — Antichain finalization uses count-based threshold

`tendermint.rs:2420-2449`. `precommit_count >= 2f+1` where `n = validator_set.len()` (includes jailed). Linear path uses `stake_quorum_threshold()` correctly. DAG-path predicate fires below 2/3-stake safety threshold whenever stake distribution is unequal — i.e. any real chain. A Sybil set of small-stake validators reaches `2f+1` count on a malicious tip while controlling < 1/3 stake. **Latent** because `light_cone_state_branches_enabled` defaults false, but the doctrine endgame is to flip it. Fix: stake-weighted threshold mirroring `check_precommit_quorum` + filter jailed.

### H12 — `block.parents` not validated, not in `block_hash`

`tendermint.rs:4837-4880` (mcc_full proposal acceptance) + `:4131-4280` (block_hash). Multi-parent extension is read on the proposer side but never validated on receivers, and the digest excludes it entirely. Two validators receiving different `block.parents` for the same proposal hash identically. Light-client header verification of multi-parent claims is structurally impossible. Fix: receiver-side gate (`parents ⊂ light_cone_dag`, antichain, distinct, bounded by `max_concurrent_forks`) + extend `block_hash` to include `parents` length-prefixed (bit-compat when empty).

### H13 — `disputed_observations` operator-local; forks under enforce

`tendermint.rs:2668-2757, 5093-5117`. `disputed_observations` is inserted via local RPC and consumed by `due_refund_txs` which feeds `validate_block_refunds`. Struct doc admits "cluster-wide dispute consensus is future Phase 4.4d work" — but no guard prevents `crooks_mev_settlement_mode = "enforce"` flipping before 4.4d ships. Asymmetric disputes split validator views; innocent proposers get slashed via Phase 3.5d. Fix: refuse `enforce` activation when `disputed_observations.non_empty() && !dispute_consensus_enabled`; OR strip disputes from `validate_block_refunds`'s consumption path.

## 4. MEDIUM findings

**M1 — VRF determinism brittle to Cargo feature flip.** `vrf.rs:22-23, 94-99`. `pqc_dilithium` default-signing is deterministic; a future flip to `random_signing` enables leader-grinding. Doc claims VRF is non-deterministic (wrong). Fix: `compile_error!` guard on the feature; correct docstring; round-trip determinism test.

**M2 — VRF inputs lack chain_id + beacon binding.** `vrf.rs:202-217`. `(height, round)` only. Cross-chain replay, pre-computable VRF table once a validator holds keys. Fix: bind beacon + chain_id.

**M3 — `aggregate_verify` accepts G1 identity public keys.** `bls_portable.rs:99-105`. Identity PK contributes nothing to aggregate. Fix: reject identity in `parse_g1_pk` + same in `bls-native` (defense in depth; PoP at registration is canonical).

**M4 — EVKV envelope has no AAD path-binding.** `secret_file_store.rs:65-97`. Attacker with FS-write can swap encrypted secrets between paths; decryption succeeds with wrong semantics. Fix: add `encrypt_blob_with_aad` mirroring `bls_key_store::*_with_aad`; default callers to pass `path_aad(file_path)`.

**M5 — TOCTOU between `fs::write` and `chmod 0600`.** `main.rs:193-204`. `fs::write` uses default umask; file is 0644 between the two syscalls. Fix: `OpenOptions::new().create_new(true).mode(0o600).open(path)` — atomic.

**M6 — AAD-bound decrypt silently falls back to empty-AAD.** `main.rs:3036-3050`. `.or_else(|_| decrypt_bls_secret(...))` re-enables path-portable rollback. Fix: on successful empty-AAD load, immediately re-encrypt with current path-AAD; loud warning; deprecate fallback after grace window.

**M7 — Gossipsub auto-relays before app validation.** `service.rs:1143-1158`. `ValidationMode::Strict` only verifies libp2p sig; without `.validate_messages()` + `report_message_validation_result`, garbage payloads relay before deserialize. 4MB × 500/10s amplification across honest mesh. Fix: add `validate_messages()` to config + `report_message_validation_result` after decode.

**M8 — PoHA cert hash + re-attestation lack DST.** `poha.rs:138-149, 176-191`. Compare `DA_ATTESTATION_DST = b"evaporchain:da-attestation:v1:"` used everywhere else. Cross-protocol BLS replay surface. Fix: add `b"evaporchain:poha-cert:v1:"` and `b"evaporchain:poha-reattest:v1:"`.

**M9 — `delete_account` bypasses `pending_batch`.** `rocksdb_backend.rs:1037-1042`. `db.delete_cf(cf, addr)` direct to disk. Speculative deletes during rollback go to disk; in-memory restored from undo log; next restart finds account missing. State divergence. Fix: route through `pending_batch` like `delete_object_disk` does.

**M10 — Stakes/delegations/sentinel missing from BatchUndoLog.** `rocksdb_backend.rs:74-91, 841-922, 1176-1213`. `put_sentinel_param` and `put_sentinel_votes` write directly to disk. Speculative state survives rollback in-memory; sentinel state survives on-disk too. Fix: add four maps to BatchUndoLog; snapshot in `begin_batch` + restore in `rollback_batch`; route `put_sentinel_*` through `pending_batch`.

**M11 — WAL `compact()` truncates before write.** `wal.rs:161-195, 153-158`. `set_len(0) → write_all(WAL_MAGIC) → loop → sync_all`. Crash between `set_len(0)` and end of loop permanently loses retained heights. Fix: write to `.wal.compact-tmp` + atomic rename.

**M12 — Snapshot apply is non-atomic + leaves stale state.** `snapshot.rs:1078-1129, 344-438`. Only wipes objects/ghosts/accounts. Stakes, delegations, sentinel state, governance, vesting schedules, note_commitments, prior spent_nullifiers all survive a snapshot restore — ghost stakes processed by slashing, legitimate nullifiers blocked, partial apply leaves hybrid state. Fix: `wipe_full_state()` helper covering every CF; wrap apply in `begin_batch/commit_batch/rollback_batch`; extend `SnapshotFile` to carry the missing tables OR document snapshot is only for first-time joins.

**M13 — Unchecked `sum::<u64>()` on private-tx amounts.** `privacy_exec.rs:594, 818-819`. Debug panic / release wrap. Validator running `cargo run` (no `--release`) is one-packet crashable; release relies entirely on the Pedersen binding check. Fix: `try_fold(0u64, |acc, &x| acc.checked_add(x)).ok_or(BalanceOverflow)?`.

**M14 — `charge_gas` unchecked `+=`; CallExternal gas-return unchecked.** `vm.rs:118-127, 795`. Not reachable today via user bytecode but the `ExternalCaller` trait is `pub` — any downstream alt impl returning bogus `gas_used` drifts the counter past `gas_limit`. Fix: `checked_add` everywhere; clamp `returned = gas_used.min(gas_remaining)`.

**M15 — `hash()` builtin under-priced O(1MiB).** `vm.rs:969-989`. Flat `GAS_CALL = 10` for FNV-1a over up to 1MiB. Contract building near-1MiB string then looping `hash(big_str)` → ~10⁶ calls × 10⁶ iter = 10¹² inner steps in one block. ~13 min single-thread chain stall. Same concern for `to_string` on recursive `Map/Array`. Fix: size-scaled gas (`GAS_HASH_BASE + len/32`); audit all O(n) builtins.

**M16 — `dag_round_states` not pruned with `state_branches` LRU.** `tendermint.rs:843, 2376-2654`. `prune_state_branches` removes from `state_branches` + `light_cone_dag` but leaves `dag_round_states[victim]`. Chain-lifetime growth + O(stale_tips) per precommit's cross-fork equivocation scan. Fix: `self.dag_round_states.remove(&victim);` in the eviction loop.

**M17 — `settled_refunds` grows chain-lifetime.** `tendermint.rs:796, 5708-5710`. ~40 bytes/entry × 10 refunds/block × 10M blocks ≈ 4GB. Fix: retain by `cutoff = block.number - crooks_mev_refund_window_blocks` on every commit.

**M18 — `entropic_slash` distribution miscalibration.** `tendermint.rs:2304-2360`. `entropic_slash(stake, &[count, 1])`. `[1,1]` is uniform (max entropy → max slash); `[100,1]` is near-deterministic (low entropy → small slash). Either the slashing function is inverse-entropy (in which case current code is right and the inline comment is wrong) or it's standard entropy (in which case more violations → less slash). Fix: add a monotonicity proptest pinning the direction.

## 6. Cross-cutting themes

**Theme A: Domain separation missing across multiple primitives.** H2 (verkle leaf/internal), H3 (verkle generators), H4 (MMR), M8 (PoHA), L2 (deriveAddress) all share the same root cause: hashing untagged bytes when the same byte shape can appear in multiple contexts. Recommend a workspace-wide `evaporchain-crypto-dst` module exposing every domain tag as a `pub const`, with a single CI lint that greps for `blake3::Hasher::new()` / `Sha256::new()` calls and requires the next `.update()` to be a const from that module.

**Theme B: ParallelExecutor never reached parity with SimpleExecutor.** C3, C4, H9 are all symptoms of incomplete porting. The T1.20 tests that codify C4 as desired-behaviour are particularly damaging — they entrench the bug. Recommend a parity proptest: for every `Transaction` variant + valid state, both executors produce byte-identical post-state.

**Theme C: Trust boundaries on untrusted input.** H5 (`DACertificate::is_supermajority`), H8 (`verify_ghost_bridge_proof` keyless), H6 (BlockSync `from_height`) all fail-OPEN on attacker-controlled deserialized fields. Recommend: deserialized public API methods that operate on untrusted bytes must require a context parameter (validator set, key set, bounds) — make fail-open structurally impossible.

**Theme D: Doctrine flags can become halt vectors.** C5 + H11 + H13 are all latent until a governance flag flips (`conservation_enforcement=enforce`, `light_cone_state_branches_enabled=true`, `crooks_mev_settlement_mode=enforce`). Punch list says all three are "DONE"; this audit shows the flip would brick the chain. Recommend: each governance flag must have a pre-flip CI test that runs the corresponding code path against an adversarial fixture.

**Theme E: Unbounded growth.** M9, M10, M16, M17, L3, L10 — six places where a collection grows without bound. State branches LRU shows the pattern is being applied selectively. Recommend: a workspace-wide rule that every `HashMap<_, _>` / `HashSet<_>` / `Vec<_>` on the consensus state struct must have an explicit cap or eviction rule documented at declaration.
