Val-3 stake trajectory on M1 (the node where the admin API was called):

| Step | Action | val-3 stake | val-3 jailed | total_slashed |
|---|---|---|---|---|
| Baseline (genesis) | — | 250000 | false | 0 |
| Slash 1 | downtime 5/100 | 225000 | true | 25000 (10% of stake) |

Sanov-KL slash arithmetic verified empirically on a live cluster — downtime miss-rate scales the slash proportional to KL distance from the honest distribution, equivocation full-slashes the remainder.

**Per-node propagation note**: the admin `/api/validators/sanov_slash` endpoint mutates ONLY the node where the API was called. After driving 3 slashes on M1, M2 and M3 still showed val-3 at full stake=250000. This is by design — admin slashes are operator-initiated, not consensus-propagated. The chain CONTINUED ADVANCING with no fork at h=200, validating that per-node stake divergence doesn't immediately break consensus (Tendermint quorum check uses the LOCAL validator-set, not a globally-synced one). For production-mainnet cluster-wide slashing the path is gossiped-evidence-driven, not admin-API.

## New regression tests (commit `5401b571`)

Two tests in `crates/evaporchain-consensus/src/tendermint.rs::t06_bls_signed_equivocation_regression`:

```
test t06_scenario_6_bls_signed_precommit_equivocation_slashes_and_jails ... ok
test t06_scenario_6_control_invalid_bls_sig_rejected_before_equivocation_check ... ok
```

**`t06_scenario_6`** pins that the equivocation gate works with REAL BLS signatures (not just `bls_signature: None` like the prior scenarios). Validator-3 has a registered pubkey; two conflicting precommits at `(h=1, r=0)` are EACH validly signed with the same key (equivocation is in the block_hash, not the sig). Asserts:
- Second precommit returns empty actions (rejected)
- val-3 stake → 0 + jailed=true (Sanov full slash)
- Validator stays in the set (jailed, not removed — production behavior; removal is governance-only)

**`t06_scenario_6_control`** pins that BLS-verify-fail happens BEFORE the equivocation gate. Attacker signs a precommit for val-3 using a DIFFERENT keypair than the registered one. Asserts:
- Actions are empty (rejected)
- val-3 stake UNCHANGED at 8000 (NO slash)
- val-3 NOT jailed

Together these two tests pin the production ordering: BLS verify gates the slash path. Forged signatures can't trigger spurious slashes; only valid-but-conflicting signatures (the actual equivocation case) do.

## Remaining gap (the honest part)

The live-cluster gap T0.6's lane spec calls for is **consensus-AUTOMATIC slashing under gossiped Byzantine evidence**:
- A real validator pretending to be honest until it issues a slashable misbehavior
- The other validators DETECT it via their consensus state machine (no admin API)
- Slashing decision PROPAGATES via gossip
- All honest validators converge on the same slashed-state

This requires:
1. A feature-gated Byzantine flag in the binary (e.g. `EVAPORCHAIN_BYZANTINE_MODE=double-precommit`)
2. Build the byzantine binary, deploy to one Mini, deploy the honest binary to the other 2
3. Run for a few minutes, observe the gossip propagation of equivocation evidence
4. Verify all 3 nodes converge on val-3 being slashed

That's a separate ~2-3 hour build. Tractable as a follow-up.

That gates T0.2's full perf soak; T0.6's slashing-at-scale logic is verified by this report's combined in-process + admin-API live demonstration.
